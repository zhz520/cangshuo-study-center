## 存储加密设计

- `questions` 和已存在的 `exam_paper_questions` 的题干、选项、答案、解析合并为 AES-256-GCM 密文，保存在原 `content` 列；原 `options`、`answer`、`analysis` 分别置为 `[]`、空串、空串。
- 每条记录使用独立随机 12 字节 IV、16 字节认证标签；AAD 绑定表名和记录 ID。错误密钥、交换记录、篡改密文均会被拒绝。
- 密钥仅来自服务端 `QUESTION_ENCRYPTION_KEY`，是随机 32 字节密钥的 Base64 表示。**Web 和 APK 均不包含此密钥。**
- MySQL 驱动返回的原始表/列元数据用于恢复受保护字段，包括收藏标题、题目报告和考试评分中的别名；不恢复未被查询的答案列。
- 新增、编辑、JSON/Excel 导入、试卷题目编辑都通过加密写入服务；单条导入使用保存点，索引失败时撤回整条写入。Node 数据库适配层拒绝旧式直接写题 SQL。
- 加密后的题干搜索使用独立派生密钥生成 HMAC 位置索引，按连续字符位置匹配，仍支持中文、数学文本和 Unicode 搜索。题干不以明文存入搜索表，但索引仍暴露长度、重复和位置关系；题型、科目、标签等元数据也未加密。
- 清理历史考试记录中复制的标准答案和解析，避免在未加密的结果快照里保留题库副本；保留用户作答和得分。

加密与权限的职责不同：数据库加密保护数据库内容或转储的机密性；HTTPS 保护传输；服务端授权决定谁能取得内容。已授权终端必须能显示题目，因此仍可通过修改客户端、截图、录屏、抓取自身响应或人工整理保存这些内容。不能保证“绝不被爬取”，也不能阻止已泄露内容继续传播。

## 限流与交互

- 题目请求：每账号每分钟 60 次、每 IP 每分钟 180 次。
- 正文下发预算：每账号每小时 1000 条、每天 5000 条，每 IP 每小时 10000 条。重复请求也计数；真实管理员不受正文数量预算限制，但仍需分页和请求频率校验。
- AI：使用 `ai_day_limit_free` / `ai_day_limit_plus` 配置，默认每天 1 / 50 次，共享同一预算。预算在请求上游前原子预留，上游失败也可能消耗一次额度，避免并发绕过。
- 兑换码每账号每分钟最多尝试 5 次，新卡密使用密码学随机数生成。
- 超限返回 `429` 和 `Retry-After`；题目响应禁止缓存，并返回当前访问范围及分页状态。
- Web 和 Android 按需加载下一批，保留分页后的历史进度；显示免费预览、权限拒绝、限流、加载错误和保存失败反馈。收藏列表提供继续加载入口。
- Web 管理员导航和 App WebView 注入会向服务端确认身份，不相信 URL 中的角色；QQ 绑定票据不放在导航 URL 中。
- 题目导出保留现有功能，但只包含当前已授权、已加载的题目。
- 模拟考试的开放规则保持原业务约定，没有新增会员收费门槛；试卷表的存储已纳入加密改造。考试开始时不下发答案，提交后仍按原规则提供答案解析；这部分授权交付的内容同样可以被保存。

## 配置与兼容性

| 配置 | 要求 |
| --- | --- |
| `JWT_SECRET`、`JWT_REFRESH_SECRET` | 两个不同的强随机值，各至少 32 字节；修改后旧会话需要重新登录 |
| `QUESTION_ENCRYPTION_KEY` | 随机 32 字节密钥的 Base64；必须单独安全备份；已经加密后不能直接更换，否则原密文无法解密 |
| `BOT_API_SECRET` | 后端与机器人使用相同的私有随机值，至少 32 字节；不分发给客户端 |
| `QQ_LOGIN_APP_ID` | 与 Android QQ 登录应用 ID 一致 |
| `GEETEST_WEB_ID/KEY`、`GEETEST_ANDROID_ID/KEY` | 原服务端极验配置转入环境变量；验证地址改用 HTTPS |
| `DEEPSEEK_API_KEY` | 从私有环境配置，不再写在路由源码里；当前本地后端留空，配置有效的新密钥后 AI 服务才可用 |
| `NODE_ENV=production`、`TRUSTED_PROXIES` | 生产要求 HTTPS；TLS 在代理终止时配置实际受信代理 IP/CIDR，不能信任任意来源的转发头 |

本地与生产弱 JWT 配置已替换并补齐加密/刷新/机器人密钥。生产 `.env` 由 `www` 用户私有读取，敏感推送配置 JSON 和配置压缩包已加入后端忽略规则；本记录不包含任何密钥值。

以下变化需要同步安排上线：

1. 发布配套 Web 与 Android。旧客户端可能只显示首批题，旧 QQ 绑定请求也无法满足新的身份证明要求。
2. 先停用直接改题库的旧导入、Python 解析和修复脚本。Node 旧式写入会被拒绝；绕开适配层的 PyMySQL/原生 SQL 脚本也必须先改造，否则可能读到密文或重新写入明文。加密不是数据库权限控制，数据库写权限应只授予受信任的运维主体。
3. 历史数据库备份、binlog、原始 JSON/Excel 和旧版本源码不因本次字段迁移而自动清除明文，需要按现有备份与访问权限政策单独处理。
4. 服务端在安全表缺失、题库尚有明文、密钥不正确时拒绝正常启动。当前生产已完成迁移并通过启动检查。

## 迁移步骤

工具：`apps/server/scripts/protect_question_storage.js`。没有 `--apply` 时只做读取统计；`--help` 不连接数据库。

生产切换前已生成数据库、应用源码、配置和上传文件备份，并核对压缩包与 SHA-256；数据库备份同时保存在服务器私有目录和 `D:\CodexData\backups\study-center-20261022`。密钥单独备份到同一私有目录，未写入前端或 APK。

正式切换前已在隔离副本完成全量加密，耗时约 1,180 秒，搜索索引约 536 MB；副本全量解密并核对明文指纹后，才在生产库执行事务写入。

在目标环境的后端目录执行：

```powershell
Set-Location 'D:\codeStudy\code\study.zhzgo.cn_83FYC\apps\server'
npm run security:storage
npm run security:storage -- --apply
npm run security:storage -- --verify
```

`--apply` 建安全预算表和搜索索引、必要时扩展 `content` 列、按 50 条一批在事务内加密并建立索引，完成后校验全部密文。每条记录先做加密解密往返验证再清空旧字段；失败只回滚当前批次，已提交批次仍保留。重复执行会验证已有密文并重建索引，不会二次加密。继续迁移时，错误密钥会在样本校验阶段拒绝，不能依靠更换密钥修复错误。

MySQL DDL 会隐式提交，整次迁移并不是一个可整体回滚的事务。回退必须恢复切换前备份并匹配对应代码和密钥，不能只回退后端代码。

完成迁移后已启用新后端、Web 和机器人密钥；生产 Nginx 补齐 `X-Forwarded-Proto` 后，API 与前端代理均返回 200。历史暴露的 AI、SMTP、极验等第三方凭据仍需在对应平台轮换，并验证旧凭据失效。 数据库旧密码也曾出现在历史脚本中，应单独轮换数据库账号密码；当前 3306 仅本机监听且未在防火墙放行。
